# Task audit of the AWS Cost Explorer plugin

**Date:** 2026-10-07

**Baseline:** merged `main`, commit `d74e7c864afd8fb031704e113dfbd0d9aecc2b76`.

**Security correction:** the original gRPC scanner finding below now has a correction in
the [dated security correction](#security-correction-on-2026-10-07). The upstream
advisory lists the installed stable version as patched.

**Scope:** compare the implementation and fresh checks with `TASKS.md`. The tracked tree contains 13 non-test Go files and 2,566 lines, including a 142-line test-process helper, and 44 test files with 6,624 lines. Three domain risks guided the review: billing arithmetic and attribution, credential and cache isolation, and AWS request boundaries and limits.

**Verdict:** the local validation gates pass, but the ledger overstates completion of four tasks: `CE-6.2`, `CE-6.4`, `CE-6.7`, and `CE-6.8`. Reproduced defects can return costs from another default AWS identity, substitute account totals for resource costs, omit a day through a cache collision, and combine incompatible usage units. Commitment mapping exists but isn't reachable through the public cost query. Release Please also fails on the merged commit because its token input is empty. These findings prevent an unconditional release-readiness claim.

## Prioritized fix plan

Effort estimates: small means less than half a day, medium means one or two days, and large means a week or more. Estimates include regression coverage.

### P1: isolate persistent cache data by the default AWS identity

**Task:** `CE-6.8`. **Effort:** medium.

`internal/pricing/cache.go:191` keys the answer by resource, explicit linked-account filter, timestamps, granularity, grouping, and metric. It doesn't include the default credential identity or payer. `internal/pricing/cache.go:33` gives processes a shared disk directory. `internal/pricing/calculator.go:239` accepts entries from that cache after initializing a default-chain client.

**Reproduction:** two calculators with distinct default clients share one disk directory. The first returns cost `1`. The second endpoint would return `99`, but the second calculator returns cached `1` and makes zero endpoint calls. Changing `AWS_PROFILE` or the default AWS account between processes has the same missing isolation boundary. An explicit linked-account filter doesn't protect service queries with no such filter.

**Fix:** establish a stable, non-secret billing identity scope before shared cache access, or turn off persistent cache reuse when the plugin can't establish that identity. Include it in the key and isolate existing entries without an identity scope. Add a process-restart regression with two principals. Per-request credentials already bypass the shared cache correctly.

### P1: reject unsupported resource attribution and align discovery

**Tasks:** `CE-6.7`, with consequences for `CE-1.2`. **Effort:** medium.

`internal/pricing/calculator.go:315` leaves arbitrary non-EC2 IDs as service queries. At line 251, these use `Filter=nil` and grouping by service. A resource request for `my-bucket` therefore receives account-level service totals. Multiple bucket requests can repeat those totals in a batch. A matching S3 ARN instead returns `InvalidArgument` at line 338, although `Supports` returns true at line 133. Successful `Supports` responses contain no opt-in or 14-day explanation.

**Reproduction:** request an AWS S3 descriptor with ID `my-bucket` and recent dates. The fake endpoint captures no resource filter and returns service totals. Repeat with `arn:aws:s3:::my-bucket`: discovery still claims support, but actual cost rejects it.

**Fix:** distinguish an explicit service-total query from a resource identity. Reject unsupported attribution without silently widening the query. Make `Supports` use the same classification and communicate the resource window and opt-in requirement. Preserve any intentionally supported total-query convention through an explicit contract. The README acknowledges the current fallback, but `CE-6.7` requires an unavailable-resource error. AWS documents the resource operation's opt-in and 14-day limits in its [API reference](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_GetCostAndUsageWithResources.html).

### P1: include the normalized AWS date interval in the cache key

**Task:** `CE-6.8`. **Effort:** small.

`internal/pricing/cache.go:194` uses timestamp seconds and drops nanoseconds. `internal/client/period.go:21` rounds a non-midnight end instant to the next exclusive date.

**Reproduction:** end `2026-10-04T00:00:00Z` queries an exclusive end of October 4. End `2026-10-04T00:00:00.000000001Z` queries an exclusive end of October 5. Both share a cache key. The second request makes no endpoint call and can omit the additional day.

**Fix:** derive the key from the same normalized dates used by the AWS request. Test midnight, midnight plus one nanosecond, and equivalent instants in different time zones.

### P1 completion gap: connect commitment enrichment to public queries

**Task:** `CE-6.4`. **Effort:** medium to large.

`internal/pricing/calculator.go:249` requests resource grouping or service grouping. Neither path requests reservation or Savings Plan identities. `internal/client/client.go:675` selects amortized cost only after a commitment identity exists. The commitment tests call the client with custom grouping directly, bypassing `GetActualCost`. `README.md:85` explicitly acknowledges that commitment fields remain unset.

**Fix:** design and implement a public query path that can retrieve the required commitment data within AWS API limits, then verify a commitment response through the actual gRPC handler. Preserve decimal precision and document metric selection. Until that exists, the task's production enrichment is partial even though its helper-level fixture acceptance passes.

### P2: don't add quantities with incompatible units

**Task:** `CE-6.2`. **Effort:** medium.

`internal/pricing/aggregate.go:134` adds usage quantities while retaining the first nonempty unit. Its merge key at line 161 excludes the usage unit. Production queries also request service-wide `UsageQuantity` without usage-type filters. AWS explains that such totals combine different units and can't represent meaningful usage in its [Cost Explorer command reference](https://docs.aws.amazon.com/cli/latest/reference/ce/get-cost-and-usage.html).

**Reproduction:** two rows for the same service contain `2 Hrs` and `3 GB`. Aggregation returns `5 Hrs`.

**Fix:** retrieve and aggregate only compatible usage quantities, or omit usage that the protocol can't represent honestly. Test both different units and service-wide AWS quantities. Monetary arithmetic is a separate concern and its existing precision tests pass.

### P1 operational blocker: supply the release workflow's token

**Task:** `REL-2` operational follow-through. **Effort:** small owner action.

`.github/workflows/release-please.yml:23` reads `RELEASE_PLEASE_TOKEN`. The [merged main Release Please run](https://github.com/rshade/finfocus-plugin-aws-ce/actions/runs/37611962696) fails with `Input required and not supplied: token`. The token input is unavailable to that run. This audit didn't read or set secret values.

**Next step:** the owner supplies or repairs the repository secret using the documented permissions and verifies a successful Release Please run. Then verify the generated release pull request, plain tag, release build, real archives, and checksums. Registry installation remains a separate downstream operation after assets exist. Don't substitute local snapshot success for that lifecycle.

### P2: propagate the release version into discovery

**Tasks:** `CE-1.3`, `REL-3`, and future release correctness. **Effort:** small.

`.goreleaser.yaml:18` injects `main.version`, `main.commit`, and `main.date`, but the entry point declares none of them. `internal/pricing/calculator.go:51` sets a fixed discovery version `0.1.0`.

**Reproduction:** build with `-ldflags '-X main.version=9.9.9'`, start the binary, and call `GetPluginInfo`. It reports `0.1.0`. The first intended release has a matching version by coincidence. Subsequent releases don't.

**Fix:** inject the actual runtime version symbol and use it consistently for discovery and logging. Test a build with a non-default version over gRPC.

### P2 security debt: resolve the reachable gRPC advisory

**Evidence:** `govulncheck ./...` reports [gRPC server panic advisory](https://pkg.go.dev/vuln/GO-2026-6443), a server panic caused by missing authority or Host headers, in gRPC v1.84.0. Its trace reaches `pluginsdk.Serve` from `cmd/plugin/main.go:75`. The scan reports a fixed version. Select a supported upstream dependency update compatible with the SDK.

The plugin listens on `127.0.0.1`, so the inspected deployment exposes this path to local clients rather than arbitrary remote clients. This is a scanner-confirmed reachable advisory, not a separately reproduced exploit. The task ledger already records it, and `.github/workflows/test.yml:31` allows vulnerability-scan failure. A green workflow therefore doesn't imply a clean vulnerability result.

## Security correction on 2026-10-07

The original dependency-security assessment and P2 security-debt finding in this report
mistook a scanner result for an applicable vulnerability. Rechecking
`govulncheck ./...` still exits 3 and reports `GO-2026-6443` against gRPC v1.84.0,
but the [gRPC maintainer advisory](https://github.com/grpc/grpc-go/security/advisories/GHSA-2v4p-qf9q-27wj)
explicitly lists v1.84.0, v1.83.2, and v1.82.2 as patched. It describes the panic
in servers configured with `xds.NewGRPCServer()`. This plugin uses the SDK's
ordinary gRPC server.

The installed v1.84.0 transport contains the fix:
[transport source, lines 525–529](https://github.com/grpc/grpc-go/blob/v1.84.0/internal/transport/http2_server.go#L525-L529)
rejects a request when both `:authority` and `Host` are absent, before processing
the remote procedure call. This source matches the downloaded dependency inspected locally.

The [Go vulnerability database](https://pkg.go.dev/vuln/GO-2026-6443) includes an
affected interval from `v1.84.0-dev` to
`v1.85.0-dev.0.20260825072537-93e31b48545e`. Stable v1.84.0 falls within that
version interval even though it includes the fix. The resulting scan
diagnostic is a version-range false positive. The dependency remains on the
stable release, v1.84.0. This advisory requires neither a development release
nor a downgrade. The vulnerability scan remains advisory in continuous integration and isn't
a clean scanner result.

This correction doesn't resolve the other historical audit findings. The missing
`RELEASE_PLEASE_TOKEN` remains an owner action: configure it through repository
Settings and verify a Release Please run. The audit and fixes neither accessed nor changed secrets.
